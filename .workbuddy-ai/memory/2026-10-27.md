# 2026-10-27

## SQL Editor 代码审查：search_path 跨租户读取缺陷

审查 `apps/api/src/sql-editor/sql-editor.service.ts:123-131` 的 `neonSql.transaction` 片段，确认：

- `@neondatabase/serverless@1.1.0` 的 `transaction()` 是把查询数组打成 `{queries:[...]}` 单次 POST 到 batch 端点，服务端在同一个隐式事务里顺序执行；`SET LOCAL` 因此生效，第二条失败整体回滚。但 `SET LOCAL` 一旦脱离事务块只产生 WARNING 不报错（fail-silent）。
- 核心缺陷：`SET LOCAL search_path TO "<proj_x>", public` 把 `public` 放进解析链末尾。PG 找不到表时不报错、继续往下找，于是 A 项目查询未建的表会静默命中 `public` 里的对象。
- `public` 里正是平台控制面（drizzle 默认 schema）：`users`(password_hash)、`organizations`、`projects`(db_schema/anon_key/service_role_key)、`org_members`、`query_history`、`storage_*`。
- 全库共用一个 DB 角色，仓库内无 GRANT / RLS / SET ROLE（已 grep 确认）。schema 只是命名空间，不是权限边界：`SELECT db_schema FROM projects` → `SELECT * FROM proj_xxx.t` 即可拖全库。
- 其他：`readOnly:false` 关掉了唯一 DB 层护栏（驱动支持 `Neon-Batch-Read-Only` 头）；黑名单 3 条前缀匹配形同虚设；catch 把所有错误压成 400 并回传 PG 原始 message；`parseSingleStatement` 用 split(';') 有假阳性；columns 从 `rows[0]` 推导，空结果集丢列名。
- 修法分层：去掉 public + 只读事务 + statement_timeout（止血）→ per-project DB role + REVOKE public + 控制面搬出 public（正解）→ owner/admin 限定 + AST 策略 + 审计。
